# 上板 Bring-up 清单（拿到硬件后按顺序做）

> 原则：**先能看见 → 先能停住 → 一次只开一个变量**。
> 每一步都要有明确判据，不满足就不许进下一步。

---

## 0. 上电前（不接电，10 分钟）

- [ ] 两板固件能编过：`cmake --build Chassis/build/w`、`cmake --build Gimbal/build/w`
- [ ] `docs/units_and_protocol.md` 里的「待填参数」已抄成实机值
- [ ] 4 个轮子已离地（垫箱子），云台周围无干涉
- [ ] 遥控器急停位放好（**左拨杆 Down**），手放在拨杆上

---

## 1. 保活（第一件事）

- [ ] `CommTask()` 里的 `HAL_IWDG_Refresh(&hiwdg)` 已就位
- [ ] 板子能连续跑 > 1 s 不复位（Ozone 连上不中断，或串口持续打印）

> 不喂狗的话底盘板 0.3 s、云台板 0.6 s 一轮复位，什么都调不了。

---

## 2. 建立观测通道

- [ ] Ozone 打开 `Chassis/chassis.jdebug` / `Gimbal/gimbal.jdebug`
      （已配好 `STM32F407IG` + SWD，加载 `build/omni_chassis.elf`）
- [ ] Live Watch 挂上：`gimbal_side.rx_count`、`rc_lv`、`life_state_`、`motor->angle()`
- [ ] **⚠️ 打硬件断点前必须断电或轮子离地**：断点会冻结 TIM6 的 1 ms 中断，
      电机保持最后一条电流指令继续转

---

## 3. 只读通道（不驱动任何电机）

### 3.1 CAN 接收

- [ ] `CommTaskInit()` 里已补 `HAL_CAN_Start()` +
      首次 `HAL_CAN_ActivateNotification(RX_FIFO0/1_MSG_PENDING)`
      （骨架原来没有，不补就永远收不到帧）
- [ ] 手转一个 M3508，对应 ID 的接收计数增长，`motor->angle()` 连续变化
- [ ] 判据：转哪个轮子只有那个 ID 涨

### 3.2 DBUS

- [ ] 摇杆拉满，`rc_lv` 到 ±1
- [ ] 右拨杆 Up / Mid / Down 分别读出 **1 / 3 / 2**
- [ ] 判据：回调里重启了接收（不重启只能收到一帧）

---

## 4. 单电机（最危险的阶段，逐个来）

- [ ] 只给一个电机 `raw = +500`，持续 2 秒，记录转向
- [ ] 方向不符 → 改 `ins_motor.cpp` 的 `dir`
- [ ] 4 个轮子正方向一致（推车前进时四轮同号）
- [ ] 云台：确认 DM 的 `is_enabled()` 变 true（上电失能，不发指令不反馈）
- [ ] 云台先给 ±5° 小阶跃，kp 从小加，kd 必须非 0

---

## 5. 状态机（用 Ozone 改变量，不用断点）

- [ ] 用 Set Value 强制把 `life_state_` 改成 `Dead`，确认所有电机输入变 0
- [ ] 急停档 → 所有电机 input == 0
- [ ] 拔遥控 → 约 100 ms 后归零
- [ ] 判据：切状态时 PID 积分被 `Reset()`，切回 Working 不会突跳

---

## 6. 双板通信

- [ ] 先单向：底盘板只发，云台板只看 `rx_count` 增长
- [ ] 再双向：同一物理量（比如一个已知常数 1.234 rad）两板解出来一致（差 ≤ 1 LSB）
- [ ] 拔任一板 CAN 线 → 另一板约 100 ms 后进 Dead、电机归零
- [ ] 判据：两端缩放比例一致（不一致会「看着通了其实数值差几个量级」）

---

## 7. 三种模式（整车，轮子着地前先离地试）

- [ ] 分离：摇杆各方向与转向都符合直觉
- [ ] 跟随：转动云台，底盘自动追着转；平移方向不变
- [ ] 小陀螺：拨轮控制自旋速度，**平移方向仍然跟着云台**（核心验收点）
- [ ] 转动云台 90° 后推杆，车朝云台指向前进

---

## 8. 看门狗（最后做）

- [ ] 加一个调试标志跳过喂狗，或用 `__BKPT()` 卡在喂狗前
- [ ] 底盘板约 **300 ms** 复位、云台板约 **600 ms** 复位
- [ ] 复位后能自动恢复（不要求「不死」，只要求「不失控」）
- [ ] **⚠️ 喂狗只能有一个入口**：放中断回调里会掩盖主循环卡死，
      验收演示时会直接判「谎称已实现」

---

## 9. PID 整定（J-Link 已就绪 → 用 Ozone）

- [ ] Ozone Timeline 画「目标 / 实际 / 输出」三条曲线
- [ ] 先 P 后 D，最后补少量 I；每次只改一个参数
- [ ] 判据：阶跃无超调（或超调 < 5%）、稳态误差可接受、无高频抖动
- [ ] yaw 注意 359° → 1° 过零：转一圈不能反向大转
- [ ] pitch 注意软件限位：到限位时应「顶住」而不是抖

---

## 附：常见「编译过但上板废」清单

| 症状 | 最可能原因 |
|---|---|
| 收不到任何 CAN 帧 | 没调 `HAL_CAN_Start()` |
| 只能收到一帧 DBUS | `HAL_UARTEx_RxEventCallback` 里没重启接收 |
| 板子周期性重启 | 忘了喂狗（底盘 0.3 s / 云台 0.6 s） |
| 跟随模式越转越快 | 轮电机 `dir` 填反，闭环变正反馈 |
| ping 平移方向反了 | `kFrameDeltaSign` 符号 |
| 云台 359° 附近来回甩 | 角度差没过 `WrapToPi()` |
| 双板「通了」但车乱跑 | 两端缩放比不一致 |
| 屏蔽喂狗板子也不复位 | 在中断回调里也喂了狗 |
